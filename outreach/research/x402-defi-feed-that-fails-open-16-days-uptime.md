## 2. The trial fails *open*, not closed

Most metered free trials fail **closed**: hit the rate-limit backend at the wrong moment and you get a 500 or a lockout — right when an agent is mid-evaluation and about to decide whether to wire a wallet. We hit exactly that bug on our busiest path and fixed it the other way.

Our per-IP daily trial counter lives in Cloudflare KV. KV has a free-tier daily write cap. When it's exhausted (or KV is simply unreachable), the counter write throws. The fix (`src/index.ts`, `trialToken` / `trialQuota`) wraps every counter read/write in a guard and, on *any* KV failure, **serves the real result uncounted** rather than erroring:

```
  } catch {
    return { token: raw, left: null }; // serve the real token uncounted
  }
```

The counter is a best-effort rate limiter, never a correctness gate. Bounded downside: a few extra free pulls on a busy day; KV resets daily. You never get a 500 from our side because *we* ran out of trial budget. That's a deliberate design choice, stated in the code comment, not a footnote.

## 3. The feed returns a decision, not just an APY

A raw yield aggregator is a lookup. We pulled `yields.llama.fi/pools` live while writing this: **15,992 pools**, and the row schema has no `verdict`, no `risk_score`, no `decision` field — `chain, project, symbol, tvlUsd, apyBase, apy, apyPct7D, apyPct30D, ilRisk, predictions…`. Great data. Zero opinion. Your agent still has to decide *whether to enter*.

`/defi/yields` closes that loop. The free preview surfaces the ranked pools **and** hands the agent a pre-filled deep-link to the decision — it carries the exact pool id forward, so the agent doesn't re-type anything:

```

  /defi/yield-entry-verdict?pool=747c1d2a-c668-4682-b9f9-296708a3dd90

It's a model-derived forecast meant to *support* a decision, not replace one, and it is not financial advice or a guarantee — but it is the one field the raw feed never returns.
